# Phase 1 — Slice scaffolding & shared primitives

Covers plan sub-phases 1-a, 1-b, 1-c (see `documentation/7136-plan.md`).

## What was done

### 1-a — Routing/nav registration
New `DashboardV2` slice registered at all four points the codebase requires for a routable page:
- `src/Core/Domain/Route.ts` — added `"DashboardV2"` to the `kinds` tuple.
- `src/Slices/DashboardV2/Core/Route.ts` (new) — `path = "/dashboard-v2"`, `environmentRole: "Required"`, `generateLabel: () => "Dashboard V2"`.
- `src/Slices/DashboardV2/index.tsx` (new) — barrel, mirrors `Dashboard`'s.
- `src/UI/Routing/PrimaryRouteManager.ts` — import + `routeDictionary.DashboardV2`.
- `src/UI/Root/PrimaryPageManager.tsx` — import + `pageDictionary.DashboardV2` → `<DashboardV2Page />`.
- `src/UI/Root/Components/Sidebar/Navigation/Group.ts` — new nav link in the `envrionment` group, right after `Dashboard`.
- `src/UI/Routing/Paths.ts` — **not listed in the original plan**, but is a fourth exhaustive `Record<RouteKind, string>` the compiler enforces; added `DashboardV2: DashboardV2.path` here too. Caught by `tsc`, not by inspection — worth remembering for any future new route.

### 1-b — Shared Environment Health primitives
All under `src/Slices/DashboardV2/UI/Components/`:
- `StatusIndicator.tsx` — colored dot + text label (`healthy`/`attention`/`danger`). Status word is always rendered as text, never color-only.
- `HealthColumn.tsx` — one health-column primitive (title + status word + stat lines), reused for Services/Resources/Compiles/Agents.
- `OrchestratorCard.tsx` — env identity + "Switch" trigger (currently a no-op `onSwitchClick?`) + Operational/Attention verdict + checklist.
- `HealthCardGrid.tsx` — layout container: orchestrator slot + N column slots separated by `Divider`s.

All four take plain props (no data hooks) per the plan's "static props only" scope for this phase.

### 1-c — Full-page layout scaffold
- `src/Slices/DashboardV2/UI/EnvironmentHealthRow.tsx` (new) — composes the header (title/subtitle/"Updated X min ago"/"Last 7 days" button/Refresh button, all static) with `HealthCardGrid` fed by **hardcoded values taken from the design screenshot** (e.g. "68 instances · 62 healthy · 4 warning · 2 danger"). None of these buttons are wired to behavior yet — that's Phase 4.
- `src/Slices/DashboardV2/UI/Components/PlaceholderSection.tsx` (new) — generic titled card with "Coming soon" body, standing in for the 4 not-yet-built blocks.
- `src/Slices/DashboardV2/UI/DashboardV2.tsx` (new) — page body: Environment Health row, then Latest Compile Reports placeholder, then a two-column Orchestrator/Resource Manager placeholder row, then Orchestration Engine placeholder — matching the full design's block order.
- `src/Slices/DashboardV2/UI/Page.tsx` (new) — top-level page, mirrors `Dashboard/UI/Page.tsx`'s loading/error/success gate on `useGetEnvironmentDetails`.
- `src/UI/words.tsx` — new `dashboardV2.*` namespace (title, nav label, placeholder text, and all Environment Health row copy).

## Assumptions / decisions made
- Route path `/dashboard-v2`, kind `DashboardV2` — new/separate from `Dashboard`, not replacing it (per the plan's Decision in §1).
- Nav label and page title both literally say "Dashboard V2" — a placeholder name; rename is trivial (one `words.tsx` entry + one `generateLabel`) whenever a real name is decided.
- The "Switch" button, "Last 7 days" range button, and "Refresh" button in `EnvironmentHealthRow` render but have no click behavior yet — intentionally deferred to Phase 3-b (Switch) and Phase 4 (range + refresh).
- Environment Health row's stat values are hardcoded to match the screenshot exactly, not derived from any placeholder/random data — this doubles as a visual acceptance check once Phase 2's real hooks replace them (values should stay close to these on a comparable test environment).
- Used a plain inline SVG triangle as a stand-in for the orchestrator "mountain" icon in the screenshot — no attempt made to source/match the exact icon; revisit in Phase 3-a if a specific icon is wanted.
